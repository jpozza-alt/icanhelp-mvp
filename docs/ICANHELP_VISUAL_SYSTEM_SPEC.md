# ICANHELP VISUAL SYSTEM SPEC

## Nome do sistema visual
icanHelp Visual System - Institutional Dark

## Direcao de marca
Plataforma institucional sobria.
A sensacao visual deve ser:
- confiavel
- clara
- tecnica sem ser fria demais
- premium discreta
- confortavel para uso prolongado
- orientada a leitura e decisao

## O que nao deve parecer
- painel improvisado
- dashboard gritante
- software colorido em excesso
- landing page comercial
- interface gamer
- visual futurista exagerado

## Princípio central
O icanHelp deve transmitir:
- seguranca
- rastreabilidade
- organizacao
- criterio
- estabilidade
- maturidade

## Regra de uso da cor
1. dourado e acento de relevancia
2. dourado nao deve dominar a tela
3. azul escuro sustenta a base da interface
4. branco suave sustenta leitura
5. sucesso, erro e alerta devem aparecer apenas em mensagens e estados
6. nao usar muitas cores de status ao mesmo tempo na mesma area

## Tipografia
Estilo tipografico:
- forte
- legivel
- institucional
- sem exagero

### Hierarquia
- H1 = 36px a 40px, bold
- H2 = 24px a 30px, bold
- H3 = 18px a 20px, semibold
- body = 14px a 16px
- small = 12px a 13px
- micro label = 11px a 12px, uppercase com tracking

### Regra
- titulos devem ser curtos e claros
- subtitulos devem orientar
- corpo do texto deve evitar blocos longos
- labels em uppercase apenas para secoes e metadados

## Bordas e raios
- card_radius = 24px
- field_radius = 12px
- button_radius = 12px
- pill_radius = full

## Sombras
- usar sombras suaves e profundas
- evitar sombra forte demais
- sombra deve dar profundidade, nao chamar atencao

## Espacamento
### Escala base
- 4
- 8
- 12
- 16
- 20
- 24
- 32
- 40

### Regra
- telas devem respirar
- evitar blocos colados
- formularios devem ter agrupamento logico
- secoes importantes devem ter espacamento maior que campos isolados

## Grid e largura
- largura maxima de conteudo principal = 1280px
- cards em grid sempre com respiro
- formularios longos devem usar colunas quando fizer sentido
- evitar linhas de texto muito extensas

## Componentes base

### Topbar
Deve parecer:
- limpa
- fixa
- institucional
- discreta
- sempre escura

Elementos:
- nome da plataforma
- subtitulo pequeno
- acao primaria secundaria como sair ou voltar
- borda inferior discreta

### Sidebar futura
Quando existir, deve ser:
- escura
- simples
- icones discretos
- estados de selecionado evidentes
- sem poluicao visual

### Cards
Tipos:
- card de contexto
- card de metrica
- card de etapa
- card de formulario
- card de resultado

Regra:
- titulo forte
- texto de apoio curto
- bom padding
- borda sempre visivel
- sem excesso de linhas decorativas

### Buttons
#### Primario
- fundo dourado
- texto escuro
- uso para acao principal da tela

#### Secundario
- fundo azul profundo
- borda dourada ou borda fria
- texto claro
- uso para acao de apoio

#### Perigo
- fundo vinho escuro
- uso apenas para excluir, remover, encerrar

Regra:
- uma tela deve ter no maximo uma acao primaria realmente dominante
- evitar excesso de botoes com o mesmo peso visual

### Inputs
- fundo escuro
- borda visivel
- placeholder discreto
- foco com maior contraste
- label sempre acima
- espacamento confortavel

### Selects
- seguir a mesma linguagem dos inputs
- nunca parecer componente padrao cru

### Textareas
- grandes o suficiente para leitura
- devem parecer areas de trabalho, nao caixas apertadas

### Alerts
Tipos:
- sucesso
- erro
- alerta
- info futura

Regra:
- blocos claros
- texto curto
- sem excesso de ruido visual

### Pills e badges
Uso:
- status
- categoria
- versao
- prioridade
- etapa

Regra:
- cores controladas
- texto curto
- nao transformar a tela em carnaval de badges

## Tabelas
Tabela deve ser:
- limpa
- legivel
- com boa separacao de colunas
- facil de escanear

Regra:
- cabecalho discreto
- linhas com contraste suave
- acoes no fim da linha
- status visivel sem exagero

## Formulario
Todo formulario do icanHelp deve seguir:
1. contexto da secao
2. campos agrupados por sentido
3. acao primaria clara
4. mensagens de erro proximas do problema
5. linguagem simples

## Wizard e jornadas guiadas
O futuro modulo NR-1 deve usar visual de jornada.
Elementos:
- etapa atual
- proximas etapas
- progresso
- pendencias
- chamada clara para a proxima acao

Regra:
- o usuario deve sempre saber onde esta
- o usuario deve sempre saber o que vem depois
- o sistema deve reduzir ansiedade e duvida

## Metricas e progresso
Cards de progresso devem mostrar:
- percentual
- situacao atual
- pendencia mais importante
- proxima acao

Regra:
- progresso deve ser simples e util
- nao encher de graficos sem necessidade

## Iconografia
Quando usar icones:
- poucos
- simples
- funcionais
- consistentes

Nao usar:
- icones decorativos sem funcao
- excesso de simbolos misturados

## Linguagem visual por modulo
### Knowledge-items
- cara de biblioteca operacional
- foco em leitura, criacao e edicao

### NR-1
- cara de jornada guiada e conformidade
- foco em progresso, diagnostico e plano de acao

### Administrativo futuro
- cara de gestao e controle
- foco em visao consolidada

## Linguagem textual
Tom:
- claro
- direto
- confiavel
- sem juridiquês desnecessario
- sem parecer professoral
- sem marketing exagerado

## Estados de tela obrigatorios
Toda tela relevante deve prever:
- vazio
- carregando
- sucesso
- erro
- pendencia
- concluido

## Anti-padroes proibidos
- misturar muitos estilos na mesma tela
- usar borda diferente em cada componente
- botao principal sem destaque real
- usar dourado em excesso
- excesso de caps lock
- excesso de caixas na mesma area
- telas muito comprimidas
- componentes com cara de HTML cru

## Template oficial de pagina
Toda pagina deve ter:
1. cabecalho com titulo e subtitulo
2. acao de retorno ou contexto
3. bloco de contexto inicial
4. area principal em cards
5. estado de feedback
6. proxima acao clara

## Decisao oficial
O padrao visual oficial do icanHelp nesta fase e:
- institucional sobrio
- dark-first
- azul escuro como base
- branco suave para leitura
- dourado controlado como destaque
- foco em clareza, conforto visual e maturidade

## Ordem seguinte
1. especificacao visual oficial
2. consolidacao dos componentes base
3. refinamento das telas principais
4. continuidade da jornada NR-1 usando esse padrao
